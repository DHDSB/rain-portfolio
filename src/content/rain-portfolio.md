## 项目背景

搭建这个个人网站，主要是为了建立一个长期、稳定且由自己掌控的内容空间，用于记录个人的学习过程、技术实践、思考总结与成长经历。

相比将内容分散在不同平台，我希望通过这个网站对作品、文章和个人记录进行统一整理。网站本身不限定内容主题，未来可以根据实际需要持续扩展，并逐渐形成属于自己的公开内容档案。

## 网站功能

目前网站已经具备以下主要功能：

- 多页面内容展示，包括首页、作品页、内容页、关于页和详情页

- 支持作品、文章和个人记录等多种内容分类

- 使用 Markdown 编写和维护正文

- 通过 Pages CMS 在网页界面中管理公开内容

- 支持内容草稿与发布状态控制

- 支持首页精选内容设置

- 支持封面图片和 Markdown 正文图片

- 支持标签筛选和全站搜索

- 支持内容按发布日期自动排序

- 支持内容列表的“加载更多”

- 自动计算文章预计阅读时间

- 支持 Markdown 表格、链接、引用、列表和代码块

- 使用 GitHub Actions 自动构建并部署网站

- 支持网站分享标题、描述和 Open Graph 分享封面

## 技术实现

网站前端使用 **React** 构建，将页面拆分为多个独立组件，使导航、内容卡片、图片、页脚和不同内容区域可以分别维护。

**Vite** 负责本地开发、资源处理和生产构建。它提供了较快的开发体验，并能够生成适合静态部署的正式网站文件。

**Tailwind CSS** 用于实现页面样式和响应式布局。通过统一的样式规则，网站可以在桌面端和移动端保持较一致的视觉效果。

**React Router** 负责网站页面之间的导航。由于网站部署在 GitHub Pages 上，项目使用 Hash Router 处理静态托管环境中的页面路由。

内容以独立的 **Markdown 文件** 保存。每篇内容通过 YAML Front Matter 定义标题、分类、日期、标签、摘要、封面、精选状态和发布状态，正文则继续使用 Markdown 编写。

**Pages CMS** 提供可视化内容管理界面。新增或修改内容后，Pages CMS 会将变化写入 GitHub 仓库，再由 GitHub Actions 自动构建和部署网站。

图片统一保存在 `public/images` 目录中，并区分封面图片与正文图片。网站使用统一的图片组件处理本地环境和 GitHub Pages 环境中的资源路径。

## 开发过程

项目最初是一个集中在单个 `App.jsx` 文件中的 React 页面。随着功能逐渐增加，页面被拆分为 Header、Footer、Hero、ContentCard、FeaturedSection、LatestSection 等独立组件。

随后，项目增加了作品页、内容页、关于页、搜索页、详情页和 404 页面，并通过 React Router 建立完整的页面结构。

在内容管理方面，网站最初使用 `content.js` 保存内容数据。为了提高可读性和维护性，内容后来被迁移为独立的 Markdown 文件，并创建统一加载逻辑，自动解析每篇内容的元数据和正文。

Markdown 迁移完成后，项目接入 Pages CMS，使内容可以通过网页界面新增和编辑，而不必每次直接修改代码。

图片功能也经过了逐步完善，包括封面上传、正文图片显示、目录分类、路径兼容和加载失败处理。最终，卡片封面、详情页封面和 Markdown 正文图片都通过统一组件进行管理。

在部署方面，项目使用 GitHub Actions 自动执行依赖安装、生产构建和 GitHub Pages 发布。每次代码或 CMS 内容更新后，网站都会自动重新构建并部署。

## 当前成果

目前，这个网站已经从一个基础页面发展为一个可以实际使用的个人内容管理与展示平台。

网站现阶段可以完成以下流程：

1. 在 Pages CMS 中新增作品、文章或记录

2. 设置分类、日期、标签、摘要和封面

3. 使用 Markdown 编写正文并插入图片

4. 决定内容是否发布以及是否展示在首页精选区域

5. 保存内容并自动提交到 GitHub

6. 通过 GitHub Actions 自动构建和部署

7. 在正式网站中浏览、搜索和筛选最新内容

除了内容发布能力，网站还具备统一的页面样式、响应式布局、搜索、标签筛选、阅读时长、图片管理、基础 SEO 和分享封面等功能。

## 后续计划

现在的网站已经具备了比较完整的内容发布和展示能力。接下来，我希望把更多精力放在真实内容的积累上，而不只是继续增加功能。比起让网站看起来越来越复杂，我更希望它能够真正记录我的学习过程、作品、思考，以及一路走来的变化。

短期内，我会持续整理和发布真实的作品、文章与个人记录，进一步优化文章结构、封面图片和正文排版，也会逐步完善首页与 About 页面中的个人介绍，让这个网站更准确地表达我是谁、我正在做什么，以及我对哪些事情感兴趣。

随着内容逐渐增加，我也希望继续改善网站的阅读体验，例如优化移动端页面、完善内容之间的关联、增加相关文章推荐，并定期检查失效链接、图片路径和过时内容，让网站能够长期稳定地维护下去。

在此基础上，我计划探索接入 AI 助手。AI 助手不只是一个简单的聊天窗口，而是可以成为网站内容的阅读伙伴。访问者可以用自然语言询问某篇文章的重点、快速了解一个作品的背景、查找与某个主题相关的内容，或者获得进一步阅读的建议。对我自己来说，AI 也可以辅助整理笔记、生成摘要、检查内容结构和发现不同文章之间的联系。

更长期来看，我希望逐步加入登录与账号管理，并接入后端数据库。在拥有用户身份和数据权限之后，网站可以从一个以个人发布为主的博客，逐渐扩展为一个围绕学习、创作和知识分享的互动平台。

在这个平台中，访问者不再只是被动阅读内容，还可以根据账号保存感兴趣的文章、收藏作品、记录阅读进度、整理个人清单，或者参与经过管理的评论与讨论。如果未来有合适的需求，也可以支持其他创作者建立个人主页、发布公开内容，并围绕共同兴趣形成交流和协作。

我还希望逐步探索以下方向：

- 为作品和文章增加收藏、阅读历史与个人书签

- 增加评论与反馈功能，同时建立必要的内容管理机制

- 支持个人学习清单、阅读进度和阶段性目标

- 为不同主题建立专题页面，将分散内容整理成连续的学习路径

- 增加内容版本记录，保留文章和作品不断完善的过程

- 提供 RSS、邮件订阅或内容更新通知

- 优化搜索能力，让搜索结果不仅匹配关键词，也能理解内容含义

- 根据实际需要增加自定义域名和更完善的访问统计

- 在保护隐私的前提下，了解哪些内容真正帮助到了访问者

- 持续改善无障碍体验，让不同使用方式的访问者都能顺利阅读

当然，这些功能不会为了“看起来更完整”而一次性全部加入。每一项功能都应该来自真实需求，并在不牺牲简单性、可维护性和内容质量的前提下逐步实现。

我希望这个网站最终不只是一个展示完成品的作品集，也能记录想法如何形成、问题如何被解决、作品如何不断完善。它可以从一个个人博客开始，慢慢成长为一个连接内容、学习、创作与交流的个人数字空间。

这个网站不会被限制在某一种主题或内容类型中。它会随着我的经历、兴趣和能力一起变化，成为一个可以持续积累、自由扩展，并且值得长期维护的地方。
