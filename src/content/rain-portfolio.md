## 项目背景

搭建这个个人网站，主要是为了建立一个长期、稳定且由自己掌控的内容空间，用于记录个人的学习过程、技术实践、思考总结与成长经历。

相比将内容分散在不同平台，我希望通过这个网站对作品、文章和个人记录进行统一整理。网站本身不限定内容主题，未来可以根据实际需要持续扩展，并逐渐形成属于自己的公开内容档案。

这个项目对我来说不仅是一个网站，也是一次相对完整的开发实践。我需要考虑页面结构、内容组织、组件拆分、图片管理、内容编辑、版本控制和自动部署，并逐步把这些部分连接成一个可以长期使用的系统。

## 网站功能

目前网站已经具备以下主要功能：

- 多页面内容展示，包括首页、作品页、内容页、搜索页、关于页和详情页
- 支持作品、文章和个人记录等多种内容分类
- 使用 Markdown 编写和维护正文
- 通过 Pages CMS 在网页界面中管理公开内容
- 支持草稿与发布状态控制
- 支持设置首页精选内容
- 支持封面图片和 Markdown 正文图片
- 支持图片目录分类与统一路径处理
- 支持标签筛选和全站搜索
- 支持按发布日期自动排序
- 支持内容列表的“加载更多”
- 自动计算预计阅读时间
- 支持 Markdown 标题、表格、链接、引用、列表和代码块
- 支持首页、About、Contact 和 Footer 文案的 CMS 管理
- 使用 GitHub Actions 自动构建并部署网站
- 支持网站分享标题、描述和 Open Graph 分享封面
- 支持自定义页面标题和基础 SEO 描述
- 支持 404 页面和页面切换后自动返回顶部

## 技术实现

网站前端使用 **React** 构建，并将页面拆分为多个独立组件，使导航、内容卡片、图片、页脚和不同内容区域可以分别维护。

**Vite** 负责本地开发、资源处理和生产构建。Vite 提供了较快的开发体验，并能够生成适合静态部署的正式网站文件。

**Tailwind CSS** 用于实现页面样式和响应式布局。通过统一的样式规则，网站可以在桌面端和移动端保持相对一致的视觉效果。

**React Router** 负责网站页面之间的导航。由于网站部署在 GitHub Pages 上，项目使用 Hash Router 处理静态托管环境中的页面路由，避免直接刷新子页面时出现路径错误。

内容以独立的 **Markdown 文件** 保存。每篇内容通过 YAML Front Matter 定义标题、分类、日期、标签、摘要、封面、精选状态和发布状态，正文则继续使用 Markdown 编写。

**Pages CMS** 提供可视化内容管理界面。新增或修改内容后，Pages CMS 会将变化保存到 GitHub 仓库，再由 GitHub Actions 自动构建和部署网站。

图片统一保存在 `public/images` 目录中，并进一步区分封面图片与不同内容对应的正文图片。网站使用统一的图片组件处理本地开发环境与 GitHub Pages 部署环境中的资源路径、懒加载和加载失败情况。

## 关键设计选择

### 保持内容方向开放

网站没有被限定为某一种职业作品集或纯技术博客。

作品、文章和记录使用统一的内容模型，使网站可以随着个人兴趣、经历和内容方向持续变化，而不需要因为主题改变而重写整个网站。

### 将内容与页面代码分离

项目最初通过 JavaScript 文件管理内容。随着正文结构逐渐复杂，继续把文章保存在 JavaScript 对象中会降低可读性，也不利于长期写作。

因此，我将正文迁移为独立的 Markdown 文件，让 React 负责页面结构与交互，让 Markdown 负责内容本身。

### 使用 Git 型 CMS

当前网站主要用于发布公开内容，还没有用户系统和复杂的动态业务数据。

因此，我选择接入 Pages CMS，而不是立即引入后端数据库。Pages CMS 提供了可视化编辑体验，同时保留 Git 版本记录，并能够继续使用现有的 GitHub Actions 部署流程。

### 使用静态部署

网站当前部署在 GitHub Pages，并通过 GitHub Actions 自动构建。

静态部署结构相对简单，维护成本较低，也符合现阶段个人内容网站的实际需求。代码和内容发生变化后，GitHub Actions 会自动生成并发布新的正式版本。

### 统一图片管理

卡片封面、详情页封面和 Markdown 正文图片最初分别处理路径，容易产生本地环境与 GitHub Pages 环境不一致的问题。

后来，我建立了统一的图片组件，用于处理路径转换、懒加载和加载失败。图片也按照封面与内容 ID 进行分类，使后续查找、迁移和清理更加方便。

### 逐步增加复杂度

项目没有在一开始就加入数据库、账号系统、评论和 AI 助手，而是先完成内容展示、Markdown、CMS、图片管理与自动部署。

这种方式让我可以先验证真实需求，再决定是否增加更复杂的架构，避免为了功能数量而过早引入维护成本。

## 开发过程

项目最初是一个集中在单个 `App.jsx` 文件中的 React 页面。随着功能逐渐增加，页面被拆分为 Header、Footer、Hero、ContentCard、FeaturedSection、LatestSection 等独立组件。

随后，项目增加了作品页、内容页、关于页、搜索页、详情页和 404 页面，并通过 React Router 建立完整的页面结构。

在内容管理方面，网站最初使用 `content.js` 保存内容数据。为了提高可读性和维护性，内容后来被迁移为独立的 Markdown 文件，并创建统一的加载逻辑，自动解析每篇内容的元数据和正文。

Markdown 迁移完成后，项目接入 Pages CMS，使内容可以通过网页界面新增和编辑，而不必每次直接修改代码。

为了控制未完成的内容，网站增加了发布状态。设置为草稿的内容不会出现在首页、作品页、内容页、搜索结果和详情页中。与此同时，首页精选状态也可以独立控制。

图片功能也经过了逐步完善，包括封面上传、正文图片显示、目录分类、路径兼容和加载失败处理。最终，卡片封面、详情页封面和 Markdown 正文图片都通过统一组件进行管理。

随着内容浏览能力逐渐完善，网站又增加了标签筛选、全站搜索、加载更多和预计阅读时间。Markdown 正文也进一步支持表格、链接、引用、列表和代码块等常用排版形式。

在部署方面，项目使用 GitHub Actions 自动执行依赖安装、生产构建和 GitHub Pages 发布。每次代码或 CMS 内容更新后，网站都会自动重新构建并部署。

## 当前成果

目前，这个网站已经从一个基础页面发展为一个可以实际使用的个人内容管理与展示平台。

现在，我可以直接通过 Pages CMS 创建和维护作品、文章与个人记录，设置分类、发布日期、标签、摘要、封面、精选状态和发布状态，并使用 Markdown 编写包含图片、表格、链接与代码块的正文。

内容保存后，会自动提交到 GitHub，并通过 GitHub Actions 完成构建和部署。日常发布公开内容时，我不再需要修改 React 代码或手动执行部署命令。

项目目前形成了比较清晰的职责划分：

- React 负责页面结构、交互逻辑和视觉呈现
- Markdown 负责作品、文章和记录的正文
- Pages CMS 负责内容与页面文案的可视化编辑
- GitHub 负责代码与内容的版本记录
- GitHub Actions 负责自动构建和发布
- GitHub Pages 负责网站的公开访问

对我来说，这个项目的成果不只是完成了一个个人网站，更重要的是建立了一套可以长期使用的内容工作流。

以后新增公开内容时，我可以把注意力放在写作和整理上，而不必重复处理页面代码与部署流程。网站也不再只是一个静态展示页面，而是成为了一个能够持续更新、逐步积累并不断扩展的个人内容空间。

## 后续计划

现在的网站已经具备较完整的内容发布和展示能力。接下来，我希望把重点从继续搭建框架转向真实内容积累与使用体验改善。

### 近期计划

近期会持续整理和发布真实的作品、文章与个人记录，并进一步优化文章结构、封面图片和正文排版。

我也会逐步完善首页与 About 页面，让网站更准确地表达我是谁、我正在做什么，以及我对哪些事情感兴趣。

随着内容增加，还会继续改善移动端阅读体验、检查失效链接与图片，并根据实际内容数量决定是否增加相关文章推荐、专题页面和 RSS 订阅。

### AI 阅读助手

未来我希望探索接入 AI 助手。

AI 助手不只是一个简单的聊天窗口，也可以成为网站内容的阅读伙伴。访问者可以使用自然语言了解文章重点、询问作品背景、查找相关内容，或者获得进一步阅读建议。

对我自己来说，AI 也可以辅助整理笔记、生成摘要、检查内容结构，并发现不同文章之间的联系。

### 互动平台方向

更长期来看，我希望逐步加入登录与账号管理，并接入后端数据库。

在具备用户身份和数据权限后，网站可以从个人发布型博客，逐渐发展为一个围绕学习、创作与知识分享的互动空间。

访问者可以收藏感兴趣的内容、保存阅读进度、整理个人清单，或参与经过管理的评论与讨论。

如果未来出现真实需求，也可以支持其他创作者建立个人主页、发布公开内容，并围绕共同兴趣进行交流。

可能继续探索的方向包括：

- 为作品和文章增加收藏、阅读历史与个人书签
- 增加评论与反馈功能，并建立必要的内容管理机制
- 支持个人学习清单、阅读进度和阶段性目标
- 为不同主题建立专题页面和连续的学习路径
- 增加内容版本记录，保留文章和作品不断完善的过程
- 提供 RSS、邮件订阅或内容更新通知
- 让搜索功能不仅匹配关键词，也能够理解内容含义
- 根据实际需要增加自定义域名和更完善的访问统计
- 在保护隐私的前提下，了解哪些内容真正帮助到了访问者
- 持续改善无障碍体验，让不同使用方式的访问者都能顺利阅读

这些功能不会为了让网站显得复杂而一次性全部加入。每一项功能都应该来自真实需求，并在不牺牲简单性、内容质量和可维护性的前提下逐步实现。

我希望这个网站最终不只是一个展示完成品的作品集，也能够记录想法如何形成、问题如何被解决，以及作品如何不断完善。

它会随着我的经历、兴趣和能力一起变化，成为一个可以持续积累、自由扩展，并且值得长期维护的个人数字空间。
